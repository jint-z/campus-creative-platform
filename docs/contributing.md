# 分支与 Pull Request

1. 从最新的 `main` 创建分支。功能用 `feat/简短描述`，修复用 `fix/简短描述`，文档用 `docs/简短描述`，例如 `docs/setup-note`。
2. 在分支上提交单一目标的修改。提交信息简述目的，例如 `docs: 补充后端启动说明`。检查暂存差异，确认本地配置、账号凭据、依赖和构建产物未被跟踪。
3. 执行 README 中与改动相关的检查。向 `main` 发起 PR，填写改动、自测结果和接口或配置影响。
4. 日常改动通过 PR 进入 `main`。作者完成相关自测、解决冲突和阻断问题后，可自行合并。必需审批人数为 0，成员可按需邀请他人审查。
5. 接口路径按模块使用小写路径段。修改公共 API 或启动配置时同步更新对应说明。合并后组员更新本地 `main`。
